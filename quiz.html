Question 1: Mirai Botnet

What was the primary infection vector used by the Mirai botnet (2016) to compromise IoT devices?

Correct answer: b
Mirai scanned the internet for IoT devices with open Telnet (port 23) or SSH (port 22), then tried a list of ~60 default username/password pairs. It infected ~600,000 devices—mostly IP cameras and home routers—and launched record-breaking DDoS attacks (1.1 Tbps against OVH, 620 Gbps against Krebs on Security) [1].

Question 2: OWASP IoT Top 10

Which of the following is NOT one of the OWASP IoT Top 10 vulnerability categories?

Correct answer: d
The OWASP IoT Top 10 focuses on IoT-specific issues: 1) Weak passwords, 2) Insecure network services, 3) Insecure ecosystem interfaces, 4) Lack of secure update mechanism, 5) Use of insecure/outdated components, 6) Insufficient privacy protection, 7) Insecure data transfer/storage, 8) Lack of device management, 9) Insecure default settings, 10) Lack of physical hardening [1]. SQL injection is a web application vulnerability (OWASP Web Top 10), not specific to IoT firmware.

Question 3: Secure Boot

What is the "Root of Trust" in a secure boot chain?

Correct answer: b
The Root of Trust is an immutable ROM burned into silicon at fabrication; it cannot be modified. The CPU verifies a cryptographic signature on each boot stage before executing it, starting from this Root of Trust. The chain continues: ROM → signed bootloader → signed application firmware → runtime [Lesson 2].

Question 4: OTA Updates

Why is A/B partitioning (dual-bank flash) critical for OTA updates on IoT devices?

Correct answer: b
A/B partitioning (dual-bank flash) enables atomic updates: the update writes to the inactive bank, verifies the full image hash, then atomically swaps the active partition. If power fails mid-update, the device simply boots the previous (still valid) firmware—clean rollback. Without this, a power loss during update bricks the device [Lesson 2].

Question 5: Device Identity & Provisioning

What is the difference between IDevID and LDevID in IEEE 802.1AR?

Correct answer: b
Per IEEE 802.1AR: IDevID (Initial Device Identifier) is a globally unique, manufacturer-provided X.509 certificate burned in at fabrication and stored in a way that protects it from modification. LDevID (Locally Significant Device Identifier) is issued by the network administrator during provisioning, bound cryptographically to the IDevID, and used for daily operations. Operational certs (LDevID) are typically short-lived (e.g., 90 days) and renewed via EST (RFC 7030) [Lesson 2, Ref 2].
